## 硬约束
1. [scope: all] 可拆分、可并行的耗时任务，积极使用 Hermes 的delegate_task机制；只派独立、只读或互不写同一文件的任务，结果由主会话核验文件、命令和远端 hash，不凭子代理自述。
2. [scope: all] 单次即时命令、需要我当场看屏或交互的操作，直接执行，不派发。
3. [scope: all] 网页搜索/抓取优先用 DeepSeek 官方 Search / Fetch API（/v1/tools/search、/v1/tools/fetch），不要把搜索请求塞进对话模型；接口不可用时再用内置 web_search / web_extract，并说明。
4. [scope: all] 无特殊情况（撞红线、缺权限/凭据、需要不可逆操作、两种方案的成本或风险无法自行验证）时，自行调研→研究→分析→决策→推进；非必要不把方向或下一步抛回，不是必须我看或操作的尽量后台执行或 headless，并积极用 delegate_task 保持自动继续，做完再报。
5. [scope: all] 当前 Hermes 版本为 v0.22.2 稳定版；优先用内置技术栈（python 3.14.7 / git 2.53.0+3 / node 26.7.0 / npm 12.0.2 / uv 0.12.3，位于 %LOCALAPPDATA%\hermes\tools\）。
6. [scope: all] 本对话负责的项目里有纳入版本控制的改动，按可交付粒度提交到本地仓库；任务收尾把当前分支 push 到 origin，并核对远端 HEAD。提交前只暂存本任务文件，不提交别的 session 未完成的改动；push 前过红线第 6 条的三项自检；项目有测试/自检就先跑，失败不 push。
7. [scope: all] 只处理本对话负责的项目；别的 session / 项目的事，不主动查、不主动报、不主动动，除非我明确点名。点名只解除本条的查看/汇报限制，不构成红线授权；红线优先于硬约束。

## 红线（默认禁止；未经我明确授权不得进行；授权只对点名事项有效）
1. 禁止重启/停止 Hermes、网关、桌面后端。

4. 禁止删记忆/会话库/备份。
5. 禁止把仓库改为公开、对外发布或发 Release；向已有公开仓库正常 push 不在此列。
6. 推仓前必须过凭据、隐私、本机绝对路径三项自检。

9. 禁止杀/停别的对话的进程与在跑任务，禁止改别线的仓。
